Cross-post short video to every platform, from your own machine.

xPST is an open-source desktop app and command-line tool that takes one short video and publishes it to YouTube Shorts, X, Instagram Reels and TikTok — using only your own accounts, storing everything locally, and never uploading anything until you confirm it.

Open source MIT OR Apache-2.0 Local-first No telemetry 44 CLI commands

What xPST is not: it is not a hosted service, it does not post on behalf of other people, and it does not operate an account you cannot see. It is a tool you run.

How it works

The whole flow is four steps, and nothing leaves your machine until the last one:

  1. Connect your accounts once. xPST runs its own OAuth flow for each platform and stores the resulting credentials encrypted on your device.
  2. Pick a video. Choose a local file, or pull one in from a connected source.
  3. Preflight. xPST checks the file against each destination's real limits — resolution, aspect ratio, duration, codec, file size — and shows you exactly what will be uploaded before anything is sent.
  4. Confirm and publish. Captions are adapted per platform, uploads are queued and tracked, and results come back with a real status and a real post URL per platform.

Platform support, stated honestly

xPST separates what a platform can do for you, because "connected" means different things:

PlatformPull videos inPublish outAnalytics
YouTube ShortsYesYesYes
XYesYesYes
Instagram ReelsYesYesYes
TikTokYesRequires TikTok app approvalYes

TikTok is fully supported for pulling content in and for analytics. Publishing to TikTok requires an approved developer application with TikTok's Content Posting API; until an application is approved, xPST reports that capability as blocked rather than pretending it works. Threads and Messenger exist in the product but stay switched off unless deliberately enabled.

Install

From source today — the package index release is pending:

git clone https://github.com/TysAIs/xPST.git
cd xPST
python -m venv .venv && source .venv/bin/activate
pip install -e ".[full,dev]"
xpst readiness      # tells you what is missing, if anything

Desktop builds for macOS, Windows and Linux are published as release artifacts on the releases page. Builds are currently unsigned, so macOS shows a Gatekeeper prompt on first launch: right-click the app and choose Open.

First run

xpst wizard              # guided setup: connect every platform, resumable
xpst auth status         # show exactly what is connected and verified
xpst post -v clip.mp4 -c "My caption" -p youtube,x,instagram
xpst schedule install    # let xPST fire scheduled posts automatically

Built for AI agents too

xPST exposes the same capabilities to agents that it exposes to you, with the same safety rules: non-interactive commands emit JSON automatically, every mutating action supports a dry run, and exit codes are stable and documented. A Model Context Protocol server ships in the box, so an agent gets typed tools for posting, scheduling, analytics, health and failure recovery rather than scraping a UI.

xpst post --dry-run --json     # show the exact plan, send nothing
xpst health --json             # live connectivity per platform
xpst mcp serve                 # expose tools to an MCP client

Agents get capability and readiness endpoints that report per-role truth — a platform can be ready to pull content while its publishing role is explicitly blocked. Nothing in the agent surface can bypass the same confirmation rules a human goes through.

Why local-first

Your credentials stay yours

Session data is encrypted at rest on your device. No plaintext credential is written to disk, and no credential is transmitted to us — there is no "us" server to transmit to.

No personal data in the project

The public repository contains no personal identifiers, no accounts and no secrets — verified by automated scans that run against the whole git history, not just the current files.

Read the code

Every claim on this page maps to source you can inspect at github.com/TysAIs/xPST.

Failures are reported as failures

When a platform rejects an upload, xPST records the platform's own error and marks the post failed. There are no placeholder URLs and no silent successes.
