# TikTok Setup

> **Role in xPST:** Both a **source** and a **posting destination**. xPST can download videos *from* TikTok to cross-post elsewhere, and (with the official Content Posting API configured) post *to* TikTok as well.
> **Auth:** None required for downloads. Optional **browser cookies** enable HD quality without watermarks. Posting to TikTok requires a TikTok developer app and OAuth 2.0 (see [TikTok as a destination](#tiktok-as-a-destination-content-posting-api)).

TikTok works as **both a source and a destination** in xPST. As a **source**, you tell xPST a TikTok username to watch, and it downloads that creator's new videos using `yt-dlp` so they can be re-encoded and posted to YouTube, Instagram, X/Twitter, Threads, and LinkedIn. Downloads work without any login, but enabling browser cookies unlocks higher-quality, watermark-free downloads. As a **destination**, xPST can upload videos directly to TikTok via the official Content Posting API (Direct Post) once a developer app and OAuth credentials are configured.

## Prerequisites

- `yt-dlp` installed and on your `PATH` (xPST installs it automatically; verify with `yt-dlp --version`).
- A TikTok account whose videos are **public** (the username you want to watch, e.g. `somecreator`).
- Optional: a browser (Chrome, Safari, Firefox, Edge, or Brave) where you're logged in to TikTok for cookie extraction.

---

## Step 1 — Install yt-dlp

```bash
pip install yt-dlp
yt-dlp --version
```

If `xpst connect tiktok` reports "yt-dlp not found," install it with the command above and re-run.

## Step 2 — Run `xpst connect tiktok`

```bash
xpst connect tiktok
```

The wizard:

1. Checks that `yt-dlp` is installed; warns if not.
2. Asks for the **TikTok username to watch** (without `@`):
   ```
   TikTok username to watch (without @): somecreator
   ```
3. Asks whether to enable browser cookies:
   ```
   Enable browser cookies for HD quality? (recommended) [Y/n]:
   ```
4. Saves the username and cookie flag to `config.yaml`.

```
✅ TikTok source configured for @somecreator
   Browser cookies will be used automatically for downloads.
```

> TikTok doesn't require authentication for downloads — the username tells xPST which creator's profile to scrape for new videos.

## Browser cookies for HD quality

When enabled, xPST passes `--cookies-from-browser` to `yt-dlp` on every download. `yt-dlp` reads cookies directly from your installed browser's cookie store — you don't export anything manually.

Requirements for this to work:

- You're **logged in to TikTok** in that browser (even a free anonymous account is enough to unlock HD endpoints).
- The browser is **closed** (or at least not locking its cookie DB) during the `yt-dlp` call. On macOS, Chrome/Safari may need to be quit so `yt-dlp` can read the encrypted cookie store; if it fails, try Firefox (no Keychain dependency).
- On macOS, the first `yt-dlp` cookie read may prompt for Keychain access — click **Always Allow**.

What you get with cookies:
- **HD resolution** (often 1080p) **without the TikTok watermark**, vs. the watermarked SD default that unauthenticated downloads produce.

`xpst connect tiktok` lets you pick the browser implicitly; `yt-dlp` auto-detects installed browsers. If you need to target a specific one, set it in `config.yaml`:

```yaml
accounts:
  tiktok:
    username: "somecreator"
    cookies_from_browser: true
    cookies_file: "~/.xpst/credentials/tiktok_cookies.json"
```

## Manual cookie file format

If browser extraction doesn't work (e.g. locked Keychain, headless server, Docker), you can supply a cookie file manually. `yt-dlp` accepts the **Netscape cookies.txt** format:

1. Install a browser extension like **"Get cookies.txt"** (Chrome/Firefox) while logged in to TikTok.
2. Export the cookies → save as `~/.xpst/credentials/tiktok_cookies.txt`.
3. Reference it in config:

   ```yaml
   accounts:
     tiktok:
       username: "somecreator"
       cookies_from_browser: false
       cookies_file: "~/.xpst/credentials/tiktok_cookies.txt"
   ```

### Netscape cookies.txt format

The file looks like:

```text
# Netscape HTTP Cookie File
# Generated by an extension - use with yt-dlp
.tiktok.com	TRUE	/	TRUE	1700000000	sessionid	abc123...
.tiktok.com	TRUE	/	TRUE	1700000000	sessionid_ss	abc123...
.tiktok.com	TRUE	/	TRUE	1700000000	sid_tt	abc123...
```

Each line is tab-separated: `domain`, `include_subdomains (TRUE/FALSE)`, `path`, `secure (TRUE/FALSE)`, `expiry (unix epoch or 0 for session)`, `name`, `value`. Comments start with `#`.

> JSON cookie files exported by some extensions are also accepted if named `.json` and shaped as a list of `{name, value, domain, ...}` objects, but Netscape `.txt` is the most reliable format for `yt-dlp`.

Set the file to `0600`:

```bash
chmod 600 ~/.xpst/credentials/tiktok_cookies.txt
```

## TikTok as a destination (Content Posting API)

TikTok posting (xPST *uploading to* TikTok) is supported via the official **Content Posting API (Direct Post)**. This is the official, ToS-compliant path and uses `provider_mode: official`. It requires a heavier setup than source-mode: a TikTok developer app plus a per-user OAuth 2.0 flow.

### Step 1 — Create a TikTok developer app

1. Go to <https://developers.tiktok.com/> and sign in with your TikTok account.
2. Create an app and request access to the **Content Posting API** product (Direct Post).
3. From the app's credentials page, note your **`client_key`** and **`client_secret`**.

### Step 2 — Authorize and obtain tokens (OAuth 2.0)

The Content Posting API uses OAuth 2.0. After completing the authorization flow for the TikTok account you want to post to, you receive:

- an **`access_token`** — used to publish posts, and
- a **`refresh_token`** — used by xPST to automatically refresh the access token before it expires.

You can run the connection wizard to walk through this:

```bash
xpst connect tiktok
```

### Step 3 — Configure the TikTok destination

The wizard saves the credentials for you, or you can populate the TikTok account config directly:

```yaml
accounts:
  tiktok:
    enabled: true                       # destination enabled
    client_key: "your_tiktok_client_key"
    client_secret: "your_tiktok_client_secret"
    access_token: "your_oauth_access_token"
    refresh_token: "your_oauth_refresh_token"   # enables auto-refresh
```

> Tokens are mirrored into the encrypted credential store. See [getting-started.md](getting-started.md#where-your-credentials-live) for the security model.

### Limits

- **Caption:** max 2200 characters.
- **Rate:** approximately 6 posts per minute.

See TikTok's Direct Post docs at <https://developers.tiktok.com/doc/content-posting-api-direct-post> for registering an app and the full OAuth flow. TikTok can be used as a **source** (this guide's main path), as a **destination**, or both at once.

## Troubleshooting

| Symptom | Fix |
|---------|-----|
| `yt-dlp not found` | `pip install yt-dlp` (Step 1). |
| Download fails with `HTTP 403` / "login required" | Cookies are stale or missing. Re-enable browser cookies or refresh the manual cookie file. |
| Watermark appears on downloads | You're downloading unauthenticated. Enable browser cookies (Step 2 prompt) for watermark-free HD. |
| `yt-dlp` can't read Chrome cookies on macOS | Quit Chrome fully, or use Firefox (no Keychain lock). Approve the Keychain prompt for `yt-dlp`. |
| `ERROR: unable to extract` | TikTok changed their page layout. Update yt-dlp: `pip install -U yt-dlp`. |
| No new videos found | The creator hasn't posted since your last run, or the username is wrong (don't include `@`). Check `xpst status`. |
| Duplicate posts | xPST tracks posted videos in `state.json`. If you wiped state, it may re-post. Don't manually delete `~/.xpst/state.json` unless you want a full re-backfill. |

See [troubleshooting.md](troubleshooting.md) for the cross-platform cookie-refresh and credential-reset procedures.
