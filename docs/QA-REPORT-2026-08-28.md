### Failures root-caused & fixed on this branch

**Fix 1 — deep link dropped on macOS second-instance launch (`src-tauri/src/lib.rs`).**
Observed: `open xpst://…` → LaunchServices started a NEW process with the URL as argv; single-instance plugin forwarded argv to the primary over its socket, then exited — but the shell's callback was `|app, _args, _cwd| { focus_existing(app); }`, discarding the URL. Plugin-side `handle_cli_arguments()` is cfg(windows/linux)-only, so macOS had no path for the forwarded URL. **Fix:** the single-instance callback now parses args and routes any `xpst://` URL through `handle_deep_link` (receipt marker + focus + engine forward). Verified: `outcome=forwarded:200`.

**Fix 2 — stale LaunchServices default handler (`scripts/deeplink-e2e.sh`).**
`lsregister -dump` showed 5 registered copies claiming `xpst://`; `LSCopyDefaultApplicationURLForURL` resolved to a **stale clone** (`xPST-work/xpst-deeplink/…`), so the URL never reached the QA app and no marker ever appeared. Stale handlers unregistered (`lsregister -u`); script hardened with new step 2b: pin + verify the freshly-built app as default `xpst://` handler via `LSSetDefaultHandlerForURLScheme` (swift), failing loudly if LS would route elsewhere.
