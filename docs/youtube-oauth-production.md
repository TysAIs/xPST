# YouTube OAuth: publishing your Google Cloud app to production

xPST connects to YouTube with Google OAuth 2.0. You create (or reuse) a Google
Cloud project, create an OAuth **Desktop app** client, download the client
secrets, and let `xpst connect youtube` run the browser consent once.

> **TL;DR — publish the app to production.** The single most common YouTube
> auth problem in xPST is a Google Cloud app left in **Testing** mode: Google
> issues refresh tokens that **expire 7 days** after consent, so xPST asks you
> to re-authorize every week. xPST already auto-refreshes access tokens — it
> cannot recover from the refresh token itself expiring. Clicking
> **Publish App** makes refresh tokens long-lived and ends the weekly
> re-auth cycle.

The step-by-step checklist is also available from the CLI (auto-generated by
the same code the wizard uses):

```bash
xpst connect youtube --guide           # human-readable checklist
xpst connect youtube --guide --json    # machine-readable (agents)
```

## Step-by-step

1. **Create or select a project**
   <https://console.cloud.google.com/projectcreate>
   (existing projects: <https://console.cloud.google.com/projectselector2/home/dashboard>)

2. **Open the OAuth consent screen** — Google Auth Platform → Audience:
   <https://console.cloud.google.com/auth/audience>

3. **Publish the app to production** — click **Publish App** on the Audience
   page.

   - **Testing mode** = refresh tokens expire **7 days** after consent (test
     users lose authorization at the same time). This is the root cause of the
     "xPST asks me to log in every week" problem — it is an app-status issue,
     not a code issue.
   - **Production status** = refresh tokens are long-lived.
   - YouTube scopes are **sensitive**, so a published app shows an
     *"unverified app"* warning and has a 100-user cap. Harmless for personal
     use (1 user): at the consent screen choose **Advanced → Continue**.
     Optional: run Google verification later.
   - Note: the xPST project's own Google Cloud app is already published to
     production, so tokens issued against it are long-lived. If you create
     your **own** project, repeat this step there.

4. **Create the OAuth client** — Google Auth Platform → Clients → Create
   Client: <https://console.cloud.google.com/auth/clients>
   (legacy UI: <https://console.cloud.google.com/apis/credentials> →
   **Create Credentials** → **OAuth client ID**).

5. **Application type: Desktop app.** Name it, e.g. `xPST Desktop`.

6. **Download the client JSON** and save it as:

   ```
   ~/.xpst/credentials/youtube_client_secrets.json
   ```

7. Run `xpst connect youtube` — your browser opens for the one-time Google
   approval. Sign in and click **Allow**. The token is stored encrypted and
   refreshed automatically afterwards.

## Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| xPST asks for YouTube login every ~7 days | App left in **Testing** mode; refresh token expires | Publish the app to production (step 3), then re-auth once |
| `access_denied` at consent | App in Testing and you are not a test user | Publish to production, or add your account as a Test user |
| "unverified app" warning | Sensitive YouTube scopes, app not verified | Advanced → Continue (fine for personal use) |
| `client_secrets.json not found` | JSON not saved at the expected path | Save it to `~/.xpst/credentials/youtube_client_secrets.json` |
